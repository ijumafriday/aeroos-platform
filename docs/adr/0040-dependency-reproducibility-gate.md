# ADR 0040 — Dependency reproducibility is a hard gate

Status: Accepted — 0.27.1

AeroOS MUST NOT resolve JavaScript dependencies from version ranges when `pnpm-lock.yaml` is absent. The lockfile is part of the release definition, not an optional convenience.

Consequences:

- CI, Docker builds, local verification, security audit, and production release all fail closed when the lockfile is absent.
- The package manager is pinned to `pnpm@9.15.0` and frozen installs are mandatory.
- There is no `pnpm install --no-frozen-lockfile`, conditional unlocked install, or ad-hoc `npm install` fallback in verification paths.
- A source archive may still be created for review while the lockfile is unavailable, but its manifest reports `dependencyLock: false` and it MUST NOT be promoted or represented as a production build.
- Once registry access is available, the lockfile must be generated by the pinned package manager and then validated through `scripts/dependency-gate.sh`, the full build/test suite, reproducibility check, SBOM, provenance, and image-signing pipeline.

This ADR intentionally blocks progress to lower-priority roadmap items until the remaining P0 dependency gate is closed.
